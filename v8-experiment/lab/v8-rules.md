# Правила генерации JS/TS: контракт с V8

Эти правила инвариантны к версиям Node и браузеров. Применяй их ко всему генерируемому коду без напоминаний.

1. **Стабильный shape объектов.** Объекты одного назначения (DTO, конфиги, результаты нормализации) создавай с одним и тем же набором полей в одном и том же порядке. Отсутствующие значения заполняй null, а не пропускай ключ.
   Запрещено: `{ ...base, ...(cond && { extra }) }` — условное добавление ключей порождает семейство hidden classes.
   Правильно: `{ ...base, extra: cond ? value : null }`.

2. **Инициализируй все поля в конструкторе/литерале сразу.** Не дописывай поля объекту после создания и не создавай объект по частям в разных ветках.

3. **Никогда не используй delete на объектах.** Для "удаления" присваивай null. delete переводит объект в dictionary mode необратимо.

4. **Не смешивай типы в одном поле и в одном массиве.** Поле, начавшее жизнь числом, не должно становиться строкой или null|number попеременно в горячем коде. Массив держи гомогенным.

5. **Не создавай дырок в массивах.** Не используй delete arr[i], не пиши за пределами length, не создавай new Array(n) с частичным заполнением. Дырка необратимо переводит массив в holey-режим.

6. **Горячие функции держи мономорфными.** Функция, вызываемая в цикле/на каждый запрос, должна получать объекты одного shape. Разные источники данных нормализуй к единому shape на границе, а не внутри горячего пути.

7. **Числа: следи за стабильностью типа.** Счётчики и индексы держи целыми; не меняй int-поле на дробное/строку по ходу жизни объекта.
